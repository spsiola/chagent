# Архитектура проекта Chagent

Этот документ описывает высокоуровневую архитектуру нашего ИИ-агента.

## Основные компоненты

### 1. `server.py`
Фронт-офис приложения на базе **FastAPI**.
- Поднимает веб-сервер и отдает статику из папки `src/chagent/static`.
- Открывает WebSocket-соединение (`/ws/chat`) для общения с клиентом в реальном времени.

### 2. `agent.py`
Мозг приложения (`AsyncAgent`).
- Отвечает за общение с LLM через библиотеку `openai` (или совместимые API, такие как Ollama).
- **Память и контекст (`history`):** хранит всю историю диалога в атрибуте `self.history`, что позволяет вести связную беседу. Именно здесь происходит финальная склейка `tool_calls` и `tool_results` перед отправкой в LLM.
- **Потоковая передача:** возвращает события (`info`, `message`, `tool_call`, `tool_result`, `finish`, `error`) через генератор (yield), чтобы UI мог мгновенно реагировать.
- **Фоллбэк-парсер и защита от ошибок:** имеет встроенную логику сканирования текста на наличие JSON-объектов (для моделей, выдающих сырой текст вместо API-вызова). При возникновении ошибки `JSONDecodeError` во время парсинга аргументов инструмента, подменяет сломанный JSON на пустой словарь `{}`, предотвращая HTTP 400 ошибки при следующем запросе к провайдеру.

### 3. `mcp_integration.py`
Адаптер для **Model Context Protocol**.
- Управляет жизненным циклом (запуск и безопасное закрытие через `__aenter__`/`__aexit__`) MCP-серверов (например, `@modelcontextprotocol/server-everything` через `npx`).
- Динамически читает список доступных инструментов с MCP-сервера и регистрирует их в агенте (`AsyncAgent.register_tool`).

### 4. `native_tools.py`
Набор базовых инструментов.
- Предоставляет функции прямой работы с локальной системой (`read_file`, `write_file`, `list_directory`, `run_command`).
- Инструменты регистрируются напрямую в список агента при инициализации в `main.py`, работая быстрее и стабильнее внешних MCP-модулей.

### 5. Фронтенд (`src/chagent/static/`)
- `index.html`: Базовая разметка с премиальным дизайном (Glassmorphism, темная тема).
- `styles.css`: Ванильный CSS, фокусы на анимациях, flexbox, и переменных. Обертка markdown блоков.
- `app.js`: Ванильный JavaScript. 
  - Управляет жизненным циклом WebSockets.
  - Содержит логику окна настроек (работа с промптами, вкладками "Справка" и "Инструменты").
  - Содержит функционал "Копировать диалог", который парсит видимые элементы (`innerText`) для экспорта чистого лога.

### 6. `memory_manager.py` и подсистема Памяти
- Управляет загрузкой, сохранением и динамической сборкой системного промпта.
- **Шаблонизация (`history[0]`):** Собирает финальный текст из `system_template`, `tool_rules`, `role_prompt` и списка доступных инструментов. Этот текст формирует самый первый элемент `history`.
- **Холодный старт (`init_memory`):** При отсутствии сохраненных пользовательских настроек в папке `data/`, бэкенд считывает "заводские" параметры из папки `init_memory/personality/defaults.json`. Аналогично для базовых скиллов и `mcp_config.json`.

> [!IMPORTANT]
> **ПРАВИЛО РАЗРАБОТКИ**: Вся сборка и модификация контекста (истории) перед отправкой LLM происходит строго в двух файлах: `agent.py` и `memory_manager.py`. Справка `data/HOW_IT_WORKS.md` генерируется скиллом `update-how-it-works`, который читает эти два файла. Если вы добавляете новый файл или механизм, влияющий на структуру `history`, вы **ОБЯЗАНЫ** обновить скилл `update-how-it-works`, чтобы он начал анализировать ваш новый файл.

### 7. `stats_manager.py`
Подсистема сбора и хранения статистики (SQLite).
- Записывает метрики для каждого запроса к LLM: провайдер, модель, задержка (latency), количество токенов (входящих/исходящих) и признак попадания в кэш.
- Предоставляет методы для выборки агрегированных данных и сырых логов за текущую сессию (используется для отображения в веб-интерфейсе).

### 8. `main.py`
Точка входа (Entry point).
- Инициализирует конфигурацию, проверяет провайдеров, подключает нативные инструменты (включая инструмент чтения статистики), `MemoryManager`, `StatsManager` и запускает MCP.
- Поддерживает запуск в режиме CLI или запуск веб-сервера (команда `serve`).
- Автоматически находит свободный порт начиная с `4217`.
- Содержит глобальный перехват `KeyboardInterrupt` для чистого завершения при `Ctrl+C`.
