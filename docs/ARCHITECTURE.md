# Архитектура проекта `chagent`

Проект `chagent` представляет собой модульный асинхронный фреймворк для создания ИИ-агентов. Он спроектирован с упором на расширяемость (через MCP) и надежность (через механизм переключения провайдеров LLM).

## Структура компонентов

### 1. Конфигурация (`config.py` и `config.yaml`)
Определяет параметры подключения к различным провайдерам LLM. Модели описываются списком и проверяются последовательно.
- **`AppConfig`**, **`ProviderConfig`**: Pydantic-модели для строгой типизации и валидации файла конфигурации.

### 2. Тестирование провайдеров (`llm_tester.py`)
Обеспечивает отказоустойчивость. Функция `get_working_client` пробегает по списку провайдеров из конфигурации и пытается отправить простой тестовый запрос ("Ping") к каждой модели. Первый провайдер, вернувший успешный ответ, выбирается для работы агента.

### 3. ИИ-Агент (`agent.py`)
Ядро системы, реализованное в классе `AsyncAgent`.
- **Цикл рассуждения (Reasoning Loop)**: Управляет историей сообщений и отправляет их в LLM. Если модель запрашивает вызов инструмента (tool), агент прерывает генерацию, исполняет инструмент и возвращает результат обратно модели.
- **Регистрация инструментов**: Поддерживает регистрацию как синхронных, так и асинхронных Python-функций.
- **Fallback-парсер JSON**: Включает эвристику для локальных LLM, которые могут ошибаться при генерации нативных `tool_calls` и возвращать просто JSON в тексте ответа. Агент способен извлекать такие вызовы и обрабатывать их корректно.

### 4. Интеграция Model Context Protocol (MCP) (`mcp_integration.py`)
Отвечает за бесшовное подключение внешних инструментов.
- **`MCPManager`**: Запускает внешние процессы серверов MCP (через стандартный ввод-вывод, `stdio_client`).
- Автоматически запрашивает список доступных инструментов у сервера (через `session.list_tools()`), преобразует их схемы и регистрирует их в объекте `AsyncAgent`.
- Реализует прокси-функции `execute_mcp_tool`, которые маршрутизируют вызовы от агента в соответствующие запущенные MCP-процессы.
- Отвечает за безопасное закрытие сессий при завершении работы.

### 5. Точка входа (`main.py`)
Связывает все компоненты воедино:
1. Загружает конфигурацию из `config.yaml`.
2. Инициализирует LLM через `llm_tester`.
3. Создает экземпляр `AsyncAgent`.
4. Регистрирует встроенные инструменты (например, мок-функцию `get_weather`).
5. Запускает тестовый MCP-сервер (например, `@modelcontextprotocol/server-everything` через `npx`).
6. Передает агенту начальный промпт и дожидается выполнения задачи.
7. Корректно завершает процессы MCP-серверов.

## Поток управления (Control Flow)

1. **Инициализация**: `main.py` -> Парсинг `config.yaml` -> Поиск работающей модели -> Создание агента.
2. **Настройка инструментов**: `main.py` регистрирует нативные функции -> `MCPManager` подключается к внешним серверам и регистрирует их инструменты в агенте.
3. **Исполнение**: Пользователь дает запрос агенту (`agent.run(prompt)`).
4. **Взаимодействие с LLM**:
   - Агент отправляет запрос и схемы всех доступных инструментов.
   - LLM возвращает ответ (и потенциально `tool_calls`).
   - Агент парсит аргументы, вызывает либо локальную функцию, либо делегирует вызов в `MCPManager`.
   - Результат выполнения инструмента добавляется в контекст (с ролью `tool`), и цикл продолжается, пока LLM не вернет финальный ответ.
